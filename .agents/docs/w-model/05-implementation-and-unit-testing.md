# 実装と単体テスト

## 目的と適用範囲

Taskの範囲と承認済み詳細設計契約に従ってコードと単体テストを変更し、実装者から独立したレビューを経てPRへ引き継ぎます。Task Issueは作業範囲・依存・進捗、Feature仕様は要求、Architectureはシステム制約、詳細設計はコンポーネント契約、コードと実行可能テストは実際の振る舞いの正本です。これらの正本をIssueや別の実装説明文書へ複製しません。

## 入力と開始条件

- Task Issueと完了条件、依存Taskの状態、対象ブランチとbase revision。
- 関連Feature仕様・REQ/AC、Architecture・共通仕様、承認済み詳細設計とDESIGN ID。
- 既存の対象コード、テスト、ランナー、プロジェクト固有の開発・検証手順。
- テストデータ・環境・外部依存、および対象範囲で必要なセキュリティ上の制約。

要求・契約・依存が未確定、参照先が矛盾、または実装の結果を左右するOPEN事項がある場合は推測して着手せず、影響範囲と確認事項を記録して停止します。対象Revisionと既存の変更を確認し、Taskの範囲外の変更を混在させません。

## 実装と単体テスト

- 承認済み契約とTask完了条件に必要な最小の変更を行い、既存の設計・命名・エラーハンドリングの規約に従います。
- 単体テストは実行可能なコードとして`tests/unit/`に作成または更新し、実装とは別の期待値・境界・異常系を検証します。必要なFeature略号がある場合、共通原則の`TEST-<FEATURE>-UNIT-NNN`で追跡します。
- テストは要求された振る舞いを観測可能な形で検証し、実装の内部構造や現在の出力をそのまま写すだけのテストにしません。実行可能テストをテストケースの正本とし、同じテスト手順・期待結果をMarkdownへ重複記載しません。
- 単体テストでは対象の局所ロジックを検証します。結合境界をモックで置き換えて結合保証とせず、必要な連携確認は対応する結合テストに残します。
- 実装・テストに関わる必要な更新に限定し、文書の実装逐語説明や不要な抽象化・リファクタを追加しません。

## 検証と仕様逸脱

変更に対応する単体テストを実行し、さらにTaskの完了条件が求める検証を行います。実行したコマンド、結果、未実施項目と理由を区別して記録します。失敗時は原因を分析し、テスト・コード・詳細設計・Architecture・要件のどこに問題があるかを特定して、適切な正本の担当へ差し戻します。原因を確認せずテストを弱めたり、期待結果を実装に合わせたりしません。

実装に必要な変更が詳細設計・要件・Architectureの契約を満たせない、契約が矛盾する、または新しい振る舞いの決定が必要と判明した場合：

1. 影響するREQ/AC/DESIGN/TEST ID、実装箇所、観測された事実、必要な判断を記録します。
2. 影響を受ける実装と検証を保留し、契約の正本を更新する設計・要件工程へ差し戻します。実装側だけで契約を変更しません。
3. 承認された契約変更を取得し、影響するコード・単体テスト・結合テスト観点・トレーサビリティを更新します。
4. 変更した箇所と依存する検証を再実行し、古い契約に基づくレビュー結果は流用せず、新しいRevisionで独立レビューを行います。

## 独立レビューとPRゲート

実装者とは別のレビュアーに、Task受け入れ条件、関連する仕様・詳細設計、変更差分、実行した検証を同一Revisionで渡します。レビューでは少なくとも以下を確認します。

- 完了条件とREQ/AC/DESIGNの契約を満たし、許可されていない仕様変更がない。
- 単体テストが正常系・重要な境界・該当する失敗を検証し、テスト自体の期待結果が設計契約から導ける。
- エラー処理、データ整合性、セキュリティ境界、既存動作への影響に重大な欠落がない。
- テストが実行可能で、結果が記録され、変更範囲に無関係な差分や文書との重複がない。

指摘は必須修正と提案に区別します。必須指摘を修正して検証し、変更があれば最終差分を新しいレビューへ渡します。レビュー未実施・失敗・応答なしは合格扱いにしません。AIDEを採用するRepositoryでは[PR作成前の独立レビュー規約](../aide/07-review.md)に従い、base/headの完全なSHA、取得元、判定、指摘と状態をIssueへ記録します。すべての完了条件、検証、レビューゲートを満たした後にPRを作成します。

## 出力

- 実装コードと実行可能な単体テスト。
- 実行した検証コマンド・結果、および未実施項目と理由。
- 必要な場合に更新された設計契約と関連テスト観点、IDの相互参照。
- 独立レビュー結果、指摘の処置、最終Revisionへの再レビュー記録。
- PRからTask Issueを参照し、仕様逸脱・残作業・未解決事項を明記した引き継ぎ。

規約・成果物の正本、テストID、配置は[共通原則](01-common-principles.md)に従います。作業状態・Issue・PR・レビュー記録はRepositoryのAIDEルールに従います。
