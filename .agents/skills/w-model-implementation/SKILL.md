# W-Model Implementation

Taskの限定した変更を実装し、実行可能な単体テストで検証します。適用規約は[実装と単体テスト](../../docs/w-model/05-implementation-and-unit-testing.md)、共通ルールは[W-Model開発規約](../../docs/w-model/00-index.md)と[共通原則](../../docs/w-model/01-common-principles.md)です。

## 呼び出し例

実装担当には対象を絞った必要最小限のコンテキストを渡します。ファイルが存在しない場合は省略し、未確定情報を作らず質問またはOPEN事項にします。

```text
Task: #<issue> — <目的と対象範囲>
Base/head: <base SHA> / <対象branchまたはrevision>
完了条件: <Task Issueの完了条件へのリンク>
要求: <関連Feature仕様の相対パスとREQ/AC IDのみ>
契約: <関連する詳細設計の相対パスとDESIGN IDのみ>
実装規約: .agents/docs/w-model/00-index.md, .agents/docs/w-model/05-implementation-and-unit-testing.md
対象コード: <関連する実装・テストファイルのみ>
検証: <テスト実行コマンドとTask固有の検証>
制約・OPEN事項: <該当箇所または「なし」>

この範囲だけを実装し、tests/unit/に実行可能テストを追加・更新してください。
実行結果、変更ファイル、契約との対応、未解決事項を報告してください。
仕様・契約に不足や矛盾を見つけた場合は推測で補わず、影響箇所を記録して停止してください。
```

## 手順

1. Task Issue、依存、base/head、作業ツリーを確認し、既存の変更を保護します。完了条件・関連REQ/AC/DESIGN・対象外を抽出します。
2. Feature仕様、Architecture・共通仕様、詳細設計の正本と対象コード・テストを必要範囲だけ読み、契約の確定状態、テスト実行方法、環境制約を確認します。
3. 仕様・設計の矛盾、重要なOPEN事項、依存未完了、変更範囲の不明があれば推測で実装せず、必要な判断と影響範囲を示して停止します。
4. Taskの完了条件に必要な実装と単体テストだけを変更します。実行可能テストを正本とし、実装を写すテストや重複するテスト説明文書を作りません。
5. 単体テストとTaskで求める検証を実行し、コマンド・実際の結果・未実施項目と理由を記録します。失敗時は原因を分類し、テスト・実装・設計・Architecture・要件の適切な正本へ差し戻します。
6. 契約逸脱または契約変更が必要なら、影響ID・箇所・観測事実・必要な決定を報告し、影響する実装とテストを保留します。承認済み契約更新を取得した後に影響箇所を更新し、関連テストを再実行します。
7. 実装とは独立したレビュアーに、完了条件、関連契約、変更差分、検証結果を同じbase/headで渡します。役割を分離した別サブエージェントを利用できる場合はそれを使い、実装担当自身の再確認を独立レビューとして扱いません。
8. レビュー結果をAIDEの規約に従ってIssueへ記録します。必須指摘を修正・検証し、差分が変わったら新しいRevisionを独立レビューへ再提示します。提案の採否と理由も記録します。
9. 全完了条件とゲートを確認し、PRからTask Issueを参照します。契約変更・残作業・未実施検証があれば明記し、完了したように扱いません。

## 完了ゲート

- Task範囲・完了条件に対応する実装とUnitテスト、対象Revisionの実行結果が揃い、独立Code Reviewerが最終差分・テスト・結果を確認している。
- 期待結果は要求・契約に基づき、実装の写経にしない。Unitテストコードを正本とし、Markdownへケースを複製しない。
- テスト・結果の欠落、失敗・判定不能、独立レビュー未実施、必須指摘未解決なら統合検証・QA・PRへ進まない。未実施・OPEN事項・仕様逸脱を明示し、契約変更後は再検証・再レビューする。
- 通過・引き継ぎの記録は[実装・Unitゲート](../../docs/w-model/05-implementation-and-unit-testing.md#実装unitゲート)、AIDE採用時のIssue参照・PR作成前レビューは[レビュールール](../../docs/aide/07-review.md)に従う。

## 出力

- 変更した実装・実行可能単体テストと、関連IDへの参照。
- 検証コマンドと結果、未実施検証と理由。
- 独立レビューの判定、必須・提案指摘の状態、変更後レビューの結果。
- 契約更新・差し戻し・OPEN事項・残作業の状態。
- PRとTask Issueの相互参照および引き継ぎ情報。
