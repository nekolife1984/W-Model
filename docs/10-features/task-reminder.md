# 期限リマインダー

## 状態・承認

- Feature ID：`TR`
- 状態：Human Gate承認済み、実装・検証中
- 要求元：Issue #12でのW-Model試行依頼
- 要件承認：依頼者が2026-10-07に会話上で下記の推奨仕様を承認。承認対象は元提案revision `eb3a1fb99f4ecb587c0f9c8c87bb4a4fb35a304c`。
- 実装対象：期限リマインダーを送るべきか判断し、送信Portへ一度だけ渡す小規模サンプル。永続化、実配信、分散スケジューラは含めない。

## Requirements

- `REQ-TR-001`：有効な期限付きタスクについて、期限24時間前以降かつ期限時刻より前にスケジューラが実行されたとき、担当者へリマインダーを1回送る。
- `REQ-TR-002`：リマインダーが無効なタスクには送信しない。
- `REQ-TR-003`：既に送信済みのタスクには重複送信しない。
- `REQ-TR-004`：期限時刻以降、期限なし、または期限24時間より前には送信しない。

## Acceptance Criteria

- `AC-TR-001` (`REQ-TR-001`)：期限24時間前ちょうど、および期限24時間前より後で期限より前の実行では送信対象になる。
- `AC-TR-002` (`REQ-TR-002`, `REQ-TR-003`)：無効または送信済みなら送信せず、送信済み状態を変更しない。
- `AC-TR-003` (`REQ-TR-004`)：24時間前より前、期限時刻ちょうど、期限後、期限なしは対象外。
- `AC-TR-004` (`REQ-TR-001`, `REQ-TR-003`)：対象を送信した後の繰り返し実行では二重送信しない。

## Business Rules

- `BR-TR-001`：24時間は経過時間（86,400秒）であり、暦日計算ではない。aware datetimeで表された瞬間を比較する。
- `BR-TR-002`：対象時間窓は `[due_at - 24 hours, due_at)`。窓内で実行された最初のスケジューラ呼び出しで送信する。
- `BR-TR-003`：送信成功後に送信済み状態を記録する。送信Portの例外は呼び出し元へ伝播し、再試行・重複配送制御は本サンプルの責務外。
- `BR-TR-004`：この例は単一プロセスの逐次実行を前提とし、並列スケジューラの排他・永続化は保証しない。
