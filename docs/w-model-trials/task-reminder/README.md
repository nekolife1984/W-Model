# 期限リマインダー Feature — W-Model試行記録

- 状態：工程接続の机上試行。製品コードの実装・実行可能テスト・リリースは対象外。
- Feature略号：`TR`
- 対象：このRepositoryの規約・スキルと、架空のタスク管理サービス。
- 目的：要件からQAまで成果物の引き渡しを試し、曖昧さ、契約不整合、追跡漏れの検出とHuman Gateの停止を確認する。
- 参照：[`AI_WModel_Development_Report.md` 14章](../../../AI_WModel_Development_Report.md)、[共通原則](../../../.agents/docs/w-model/01-common-principles.md)、[統括ワークフロー規約](../../../.agents/docs/w-model/08-end-to-end-workflow.md)。

## 試行手順

1. 各工程の「入力」を確認し、その工程のGenerator成果物を読む。
2. 記録された独立検証手順のシミュレーションを追い、指摘があれば記載された戻り先を確認する。
3. 要件、設計契約、テスト、Traceability、QAの間でIDと期待値を照合する。
4. [Human Gate記録](07-human-gate.md)で初回机上試行時の承認待ち停止と、その後に依頼者が承認した決定を確認する。

## 試行の結論

- 確認できたこと：本資料に対する机上の工程シミュレーションで、要求→検証観点の対応、契約とテストの照合箇所、欠落リンクの指摘、工程別の戻り先、未承認事項による停止を表現できる。
- 未確認：工程ごとの独立サブエージェントレビュー実行、製品コード・実行可能テスト・CIの動作。工程別Reviewerの判定記録は手順のシミュレーションであり、当該工程で別エージェントを実行した証跡ではない。
- 判明した改善：統括スキルの開始情報に「机上試行／実装試行」の区別と、実行していない検証の明示を追加すると誤認を避けられる。既存の停止・差し戻し規約は意図した動作を表現できたため、規約本文の変更は不要。
- 完了境界：初回机上試行の記録。下記の承認後実行により、この節に記録したOPEN事項と未実施状態は後続Revisionで解消・更新。

## 承認後の実行

依頼者のHuman Gate承認後、確定したFeature仕様・Architecture・詳細設計・Unit/Integration/Acceptance仕様・実装・Traceabilityを作成し、各レベルの実行可能テストを通しました。工程ごとの結果と対象RevisionのQA記録は、最終成果物に追加します。
